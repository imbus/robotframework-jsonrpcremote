# Tasks

Every new test that covers a change is run against a copy of the client package without that part of the change, and must fail there. A copy on `PYTHONPATH` wins over the editable install, also for the server processes that the tests start. Tests that pin behavior that stays, those of group 1, pass before and after; their task names the copies of the server or of a test library that make them fail. A copy of a library in `atests/` takes effect when the suite runs from a copy of `atests/`.

## 1. A GLOBAL library on the server

- [x] 1.1 Add the test libraries in `atests/`:
  - `GlobalCounterLib.py`: a class with `ROBOT_LIBRARY_SCOPE = "GLOBAL"`; a keyword `count(caller="")`, which returns how often the instance was called; a keyword `end_server_process()`, which ends the server process with exit code 3, named so that it does not clash with `Exit Server` of `ConnectionLossLib` in the stdio and the pipe suite; and a listener of its own (`ROBOT_LIBRARY_LISTENER`, API version 3), which appends a line with the name and the arguments of each `start_keyword`, and a line `close`, to the file `jsonrpcremote-global-counter-events.txt` in `tempfile.gettempdir()`, as `ConnectionLossLib` writes its record there;
  - `SuiteCounterLib.py` and `TestCounterLib.py`: the same `count`, with `ROBOT_LIBRARY_SCOPE = "SUITE"` and `"TEST"`, without the listener and `end_server_process()`.
- [x] 1.2 Add `atests/global_library.robot` and the nested suite `atests/_nested/counters.robot` (design decision 3):
  - `counters.robot` imports the three libraries from `tcp://127.0.0.1:${PORT}` under aliases of their own; its one test calls `Count` of each, and the `GLOBAL` library returns `${GLOBAL}`, the other two 1.
  - `global_library.robot` uses `IsolatedServerControl.py`, `NestedRobot.py`, `OperatingSystem` and `LogCapture.py`. Its test setup removes the events file and starts a server of its own on port 8287 with the three libraries; its test teardown stops the server. So each test starts with a new server and no events file, and depends on no other test. The suite names the file `${EVENTS_FILE}`, with `${TEMPDIR}`; no local variable may be called `${events}`, since Robot Framework ignores the case of variable names.

  Its tests:
  - `Only A Global Library Keeps Its Instance From One Session To The Next`: runs `counters.robot` twice with `Run Nested Suite`, with `GLOBAL:1` and then `GLOBAL:2`;
  - `Finalizing A Global Library For One Client Leaves It To The Others`: the test imports `GlobalCounterLib` with `rpc_scope=TEST` under an alias of its own, and `Count    before` returns 1. A nested run of `counters.robot` with `GLOBAL:2` is the other client, whose import is finalized when its run ends. `Count    after` then returns 3, and the events file has a `start_keyword` line with `after` and no line `close`;
  - `The Server Closes The Listener Of A Global Library Once When It Stops`, with the tag `posix`: the test imports `GlobalCounterLib` and calls `Count`; a nested run of `counters.robot` with `GLOBAL:2` is another client, whose import is finalized before the stop; the events file has no line `close`; after `Stop Jsonrpc Server`, it has exactly one.

  Run the suite once with `--randomize tests` and verify that it passes. Verify the failures in these copies:
  - the test of the sessions, with `ROBOT_LIBRARY_SCOPE = "SUITE"` in `GlobalCounterLib`, and with `"GLOBAL"` in each of the other two libraries;
  - the test of the finalize, in a copy of the server whose `_robot_finalize_library()` also calls `scope_manager.unregister_listeners()` for every other library in the keyword store, and, for its count, with `ROBOT_LIBRARY_SCOPE = "SUITE"` in `GlobalCounterLib`;
  - the test of the close, in a copy of the server that replaces `IMPORTER.close_global_library_listeners` of Robot Framework's `robot.running.namespace` with a function that does nothing, and in a copy whose `_robot_finalize_library()` calls `scope_manager.unregister_listeners(close=True)`, which closes the listener before the stop.
