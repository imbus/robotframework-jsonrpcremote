A remote keyword fails like a keyword of a library that runs locally: Robot
Framework shows the same message, logs the same traceback, and skips the test,
continues it or stops the run in the same way. A library needs nothing special
for it, and keywords such as `Run Keyword And Expect Error` work as usual.

## The message

The keyword fails with the message that Robot Framework shows for the same
error of a local keyword, without anything added:

| The keyword raises        | It fails with           |
| ------------------------- | ----------------------- |
| `ValueError("bad value")` | `ValueError: bad value` |
| `AssertionError("boom")`  | `boom`                  |
| `RuntimeError("boom")`    | `boom`                  |

A long message appears as for a local keyword, too: the report cuts it at the
limit of [`--maxerrorlines`](https://robotframework.org/robotframework/latest/RobotFrameworkUserGuide.html#limiting-error-message-length-in-reports)
of your run, and `log.html` holds the whole message.

## The traceback

At the log level `DEBUG` or `TRACE`, the traceback of the error appears in
`log.html` under the failed keyword. It shows the code of the library on the
server, and `[remote]` marks it as coming from there, like all `DEBUG` and
`TRACE` messages from the server:

```text
[remote] Traceback (most recent call last):
  File "/srv/libraries/FailingLibrary.py", line 6, in fail_normally
    raise ValueError("bad value")
ValueError: bad value
```

## Skipped, continuable and fatal failures

The [exceptions and attributes](https://robotframework.org/robotframework/latest/RobotFrameworkUserGuide.html#reporting-keyword-status)
with which a library reports them work as in a local library. This library has
a keyword for each kind of failure:

A suite with a test for each:

<Code code={suite} lang="text" title="failures.robot" />

The tests end like this:

| Test                  | Status | Message                                        |
| --------------------- | ------ | ---------------------------------------------- |
| `Normal Failure`      | FAIL   | `ValueError: bad value`                        |
| `Skipped`             | SKIP   | `not today`                                    |
| `Continuable Failure` | FAIL   | `go on`                                        |
| `Fatal Failure`       | FAIL   | `FatalError: stop all`                         |
| `Not Run`             | FAIL   | `Test execution stopped due to a fatal error.` |

- `SkipExecution` skips the test, and the rest of the test does not run.
- After `ContinuableFailure`, the rest of the test runs, and the test fails at
  its end with the message of the failure.
- `FatalError` stops the run of the suite: the following tests do not run and
  fail with a message that says so.

A fatal failure ends only that run. The server keeps running and serves the
next keyword call, from the same client or from another one.

Start the server with `robot-jsonrpcremote-server --pythonpath . FailingLibrary`
and run the suite, as in
[Getting started](/robotframework-jsonrpcremote/getting-started/). The files are
in
[`docs/examples/failures`](https://github.com/imbus/robotframework-jsonrpcremote/tree/main/docs/examples/failures)
in the repository.

## Errors that are not failures of a keyword

Some calls fail although no keyword has failed. The library import or the
keyword call then fails with the message of the server, as a normal failure:

| What happens                                                             | The message |
| ------------------------------------------------------------------------ | ----------- |
| A suite imports a library that the server does not serve                 | `Library 'OtherLibrary' is not available.` |
| A keyword call names a keyword that the library no longer has, for example after an update of the server | `Keyword 'Old Keyword' not found in library 'MyLibrary'.` |
| A keyword call arrives while the server is stopping                      | `server is shutting down` |
| A library fails to import on the server                                  | What Robot Framework says about a local library that fails to import |

This suite imports a library that the server from above does not serve:

<Code code={refusedImport} lang="text" title="refused_import.robot" />

As with a local library, the failed import is an error of the run, and the
suite goes on without the keywords of the library:

```text
[ ERROR ] Error in file '/work/refused_import.robot' on line 2: Initializing library 'JsonRpcRemote' with arguments [ tcp://127.0.0.1:8271 | OtherLibrary ] failed: Library 'OtherLibrary' is not available.
```

If a library fails to import on the server, for example because a module is
missing there, the message names the module and holds the traceback of the
library's code and the module search path of the server:

```text
Importing library 'MyLibrary' failed: ModuleNotFoundError: No module named 'a_missing_module'
Traceback (most recent call last):
  File "/srv/libraries/MyLibrary.py", line 1, in <module>
    import a_missing_module
PYTHONPATH:
  /srv/libraries
  /usr/lib/python3.12
```

The tracebacks of the server's own code stay in the server's log. To see them on
the client while you look for a problem, start the server with
[`--send-tracebacks`](/robotframework-jsonrpcremote/reference/server/#errors-and-tracebacks):
at the log level `DEBUG`, such a traceback then appears in `log.html` under the
keyword, marked with `[remote]`, and at a library import it follows the message.

## Messages that cannot be read

A server in another language can send a message that the client cannot read or
use, for example with a bad `Content-Length` or with a log message whose fields
do not fit. The session goes on, and the client writes an error to Robot
Framework's log and to the console that names the server and the problem:

```text
[ ERROR ] Problem with a message from 'tcp://127.0.0.1:8270': Received an invalid Content-Length header: 'abc'
```

The error fails no keyword by itself. If the message was the answer to a keyword
call, the call goes on waiting for its answer.
